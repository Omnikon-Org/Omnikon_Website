## 3. GitHub Audit Findings

### A. Endpoints Consumed
- `GET /orgs/Omnikon-Org`: Organization profile, public repo count, member stats.
- `GET /orgs/Omnikon-Org/repos`: Repository list, star counts, fork counts, open issues.
- `GET /repos/Omnikon-Org/{repo}/issues`: Issue listings for IssueSwipe integration.
- `GET /orgs/Omnikon-Org/members`: Public member directory.

### B. Rate-Limiting Risks
- Currently relies on **unauthenticated REST requests** (`https://api.github.com/orgs/Omnikon-Org/repos`).
- GitHub limits unauthenticated requests to **60 requests per hour per IP address**.
- If multiple visitors access the site simultaneously, client-side fetches trigger `403 Rate Limit Exceeded` errors, causing project cards or stargazers counters to break.

### C. Data Caching & Fallbacks
- The existing site includes `github_summary.json` generated by a shell script (`fetch_github_data.sh`) as a static snapshot.
- However, client-side scripts lack robust `localStorage` TTL caching or graceful fallback UI handling when live requests fail.

### D. Activity Stream Implementation
- The homepage ticker displays static string notifications (*"Dev PR merged in demon-structureize"*, *"Alina Push Layout"*) rather than real live webhook events from GitHub's Events API (`/orgs/Omnikon-Org/events`).

---

## 4. Required Improvements for Omnikon 2.0
1. **Standardized Caching Layer**: Implement client-side `localStorage` caching with a 15-minute TTL for all GitHub API requests.
2. **Server-Side API Proxy / Edge Cache**: Use a Vercel serverless proxy route `/api/github-stats` with an authenticated `GITHUB_TOKEN` to access higher rate limits (5,000 req/hr) and cache responses globally.
3. **Graceful Fallback UI**: When API rate limits are hit, display cached data alongside a developer status indicator (`SYS.INFO: Displaying cached GitHub metrics`).
4. **Live Events Ticker**: Connect the ticker feed to real GitHub public event feeds (`/orgs/Omnikon-Org/events`).
